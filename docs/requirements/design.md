本文档记录对 [`prismshot.md`](./prismshot.md)、[`index.png`](./index.png) 和 [`网页修改.docx`](./网页修改.docx) 的澄清结果，作为设计、实现与验收依据。原始需求与反馈保留不改；若来源文档与已确认结论存在歧义，以本文档中的约定为准。

## 1. 项目目标

为 PrismShot 棱镜定格制作一个中英双语、以摄影作品为核心的社团官网。网站需要具有鲜明的暗色棱镜视觉，同时保持内容易维护、移动端可用、静态部署和良好性能。

### 1.1 范围内

- 五个常驻页面：主页、活动、主题赛、画廊、关于我们。
- 一个可通过构建开关启用的一周年摄影赛独立页面。
- Next.js 静态导出，共用全局组件、视觉系统和内容结构。
- 浏览器内交互，包括菜单、语言切换、日历、活动手风琴、图片拼贴和大图查看器。
- 中文、英文完整内容及 SEO 信息。
- Cloudflare Pages 自动构建与部署。

### 1.2 范围外

- CMS 或后台管理系统。
- 数据库、用户账号、登录和表单数据收集。
- 站内投稿、投票、报名、提醒或票数统计。
- 物理准确的实时 3D 水晶光学模拟。
- 根据浏览器语言自动跳转。
- Cloudflare Web Analytics 以外的分析、广告或行为录制服务。

## 2. 技术与内容架构

### 2.1 静态站点

- 使用 Next.js，配置 `output: "export"`。
- `next build` 生成标准 `out/` 静态产物。
- 代码不依赖 Cloudflare 专属运行时，可部署到其他静态托管平台。
- 网站可以包含客户端 JavaScript 交互，但不需要运行时服务端。

### 2.2 内容维护

- 页面组件与内容分离。
- 活动、比赛、画廊、社交账号和双语文案放在有类型的 `content/*.ts` 内容模块中。
- 不使用 Markdown、JSON 或 CMS 作为首版内容源。
- 页面只负责布局、视觉和交互，通过静态导入使用内容。
- 修改内容或图片后重新构建、部署；不直接修改 `out/` 中生成的 HTML。

建议目录职责：

```text
app/                 页面与路由
components/          共享界面与交互组件
content/             有类型的中英文内容配置
public/images/       Logo、二维码等直接使用的素材
public/generated/    构建时生成的响应式图片
```

具体目录名可在实现时调整，但职责分离保持不变。

## 3. 信息架构与双语路由

| 页面 | 中文路由 | 英文路由 |
| --- | --- | --- |
| 主页 | `/` | `/en` |
| 活动 | `/events` | `/en/events` |
| 主题赛 | `/contests` | `/en/contests` |
| 一周年摄影赛（可选） | `/anniversary` | `/en/anniversary` |
| 画廊 | `/gallery` | `/en/gallery` |
| 关于我们 | `/about` | `/en/about` |

- 根路径始终展示中文，不根据浏览器语言自动重定向。
- 语言切换后停留在当前页面的对应语言路由。
- 站内导航始终保持当前语言。
- 所有已配置的面向访客文字都需要中英文版本，包括导航、正文、按钮、状态、日期文案、照片标题与说明、替代文本、页面标题和 SEO 描述；未取得的可选照片元数据可以整体省略。
- Logo 等固定品牌图片不制作中文版本；其无障碍说明仍按当前语言提供。
- 开发阶段可提供英文初稿；社团负责确认品牌名、活动名和最终英文措辞。
- 实现阶段即使用英文初稿验证布局和交互，不因最终英文尚未确认而推迟英文路由开发。
- 一周年摄影赛由构建环境变量 `PRISMSHOT_ANNIVERSARY=1` 同时启用中英文页面；默认关闭。
- 一周年摄影赛关闭时不显示导航入口、不写入 sitemap，直接访问两个路由均返回 404。

## 4. 品牌与全局视觉

### 4.1 品牌写法

- 正文、SEO 和社交分享统一使用 `PrismShot`。
- `PRISM SHOT` 只作为 Logo 图片中的视觉写法。
- 中文全称为 `PrismShot 棱镜定格`。

### 4.2 视觉方向

- [`index.png`](./index.png) 定义首页的暗色摄影、透明水晶、棱镜色散与高对比品牌氛围。
- 首页采用已确认的**居中构图**：`PRISM SHOT`、社团副标题和简介位于视觉中轴，两侧水晶负责形成画框感。
- [`index-centered.jpg`](./index-centered.jpg) 定义首页水晶的造型、体量和边缘位置；网页以独立图层组合背景、品牌文字、水晶和交互元素。
- 核心语言为黑色基调、高对比摄影、棱镜色散、精致排版、局部细线和高光。
- 构图、素材、导航结构和响应式布局根据实际内容重新设计。
- 首页使用完整的大型水晶效果；内容页只使用较轻的色散、切面、细线或局部高光，避免干扰阅读。

### 4.3 水晶效果

- 首页使用左右分离、带真实透明通道的 PNG 水晶素材进行合成。素材内容由水晶、折射高光及紧贴切面的局部光晕组成。
- 水晶素材依据 [`index-centered.jpg`](./index-centered.jpg) 的左右轮廓与 [`index.png`](./index.png) 的光学玻璃质感生成；社团提供的钻石图片用于补充材质观察。
- 水晶 PNG 提供主体造型，CSS 滤镜、渐变和混合模式提供低强度流光、色散与视差。
- 桌面端可响应鼠标位置产生轻微视差和流光。
- 不要求 WebGL、Three.js 或物理准确的实时折射。
- 移动端可以复用同一组素材并进行更大幅度的边缘裁切；低性能设备和启用“减少动态效果”的环境允许显示静态版本。
- 背景、人物、品牌文字与水晶分别保留为独立图层，便于响应式裁切和后续替换。

## 5. 导航与页脚

### 5.1 导航

- 首页导航覆盖在背景图上。
- 桌面端直接显示全部已启用的导航标签，不显示折叠菜单图标。
- 常驻导航顺序为主页、活动、主题赛、画廊、关于我们；一周年摄影赛启用时暂放在主题赛之后、画廊之前。
- 一周年摄影赛使用普通导航样式，不添加 `NEW` 标签、独立颜色或额外动画；顺序和路由在集中配置中维护，允许后续调整。
- 桌面端语言切换位于导航右侧，首页与内容页保持相同位置和样式。
- 所有内容页使用吸附式顶部导航；滚动时保留半透明深色背景，并标出当前页面。
- 移动端使用吸附栏与折叠菜单，语言切换放在展开后的菜单内。
- 菜单、语言切换和当前页面状态需要支持键盘与辅助技术。

### 5.2 页脚

- 首页不显示传统页脚。
- 除首页之外的已启用页面使用统一的简洁页脚，包含版权信息、语言切换和隐私说明锚点。
- 页脚不重复展示整组社交二维码。

## 6. 页面设计

### 6.1 主页

- 首页是单屏入口页。
- 首页正式采用居中布局，品牌名称、副标题与社团简介沿页面中轴排列。
- 不包含参考图中的 `01/05`、`SCROLL` 或 `ENTER THE FRAME`。
- 使用原始需求中的社团介绍文案。
- 主要页面入口由顶部导航承担。
- 桌面和移动端分别支持独立背景图；未提供移动端背景时，才裁切桌面图作为降级。
- 左右水晶处于最外层，形成遮罩或画框感，但不能遮挡关键文字和导航操作。
- 右侧悬浮区只显示 QQ、VRChat、Discord；点击后在新标签页打开相应外部链接。

### 6.2 活动

正式活动名称为：

1. 相聚一镜
2. 同镜搭子
3. 教练，我要学摄影

- 三类活动按周轮换，固定活动时间为每周五 21:30（北京时间，UTC+8）。
- “同镜搭子”严格以两人为一组；日历中的活动小标题为“双人组队挑战”。
- “教练，我要学摄影”的课程内容为摄影插件教学与实战，不在课程内容标签中列出构图或光影教学。

#### 活动日历

- 日历由静态内容配置生成。
- 只能在存在配置数据的月份之间切换；超出范围的前后按钮禁用。
- 同一天允许配置多个活动，并用不同标记显示活动类型。
- 点击日期后展示当天全部活动的名称和时间，不展示活动详细说明。
- 首次打开时：
  1. 当前月份已配置，则显示当前月；
  2. 否则显示最近的未来配置月份；
  3. 若全部为历史月份，则显示最新的配置月份。
- 所有时间统一按 `Asia/Shanghai`（UTC+8）判断；具体截止时间旁标明 UTC+8。
- 不提供报名、提醒或后台管理功能。

#### 活动展示

- 三类活动使用纵向手风琴，同一时间只展开一项。
- 首次进入默认展开第一项。
- 桌面端支持悬停和键盘聚焦切换；移动端使用点击切换。
- 每项支持 1–6 张图片。
- 桌面端采用一张主图加最多五张缩略图的固定高度拼贴；不足六张时自动重排，不显示空位。
- 移动端使用主图加横向滑动缩略图。
- 点击图片进入全站共用的大图查看器。

### 6.3 主题赛

#### 当期主题

- 重点展示主题名称、规则、投稿期和当前状态。
- 投稿期显示在当期主题卡片内；页面不显示投票期时间。
- 状态包括即将开始、投稿中、投票中和已结束。
- 投稿期结束后立即进入投票期，两者共用同一个阶段切换时间点；不存在赛程空档或“等待投票”状态。
- 状态根据 UTC+8 的配置日期自动判断，并提供人工覆盖字段处理延期等特殊情况。
- 若配置了群相册或投票链接，则显示外链按钮；未配置时不显示按钮。
- 投稿与投票仍在群内完成，官网不接收作品或记录票数。
- “每位成员可提交 1 张作品，无技术要求，新人也欢迎积极报名”显示为醒目的参赛须知。
- “可转赠，不兑现”显示为奖品限制说明；两者均不是 Markdown 标题。
- 奖品区将“实体喷绘”作为独立条目，说明为获奖作品的实体喷绘定制，并标注由川云集团赞助。

#### 历届冠军

- 每条历史记录必须展示冠军作品和期数；取得主题名称或作者展示名时再显示对应信息。
- 作者选择匿名时显示“匿名”。
- 日期可以作为可选辅助信息。
- 主题赛作品不自动进入活动画廊。

### 6.4 画廊

- 首版不按活动分组，也不提供类别筛选。
- 只收录社团活动历史照片；若某张主题赛照片同时适合作为活动记录，可由维护者手动加入。
- 使用保留原始比例的瀑布流布局，默认按拍摄日期从新到旧排列。
- 首次展示 24 张；点击“加载更多”后每次追加 24 张。
- 不使用无限滚动或服务端分页。
- 图片采用懒加载。

#### 大图查看器

- 点击照片后全屏查看。
- 支持左右按钮、键盘方向键和手机滑动切换。
- 支持 `Esc`、关闭按钮和适当的遮罩点击关闭。
- 显示已经提供的作品标题、说明、拍摄者和日期；缺失字段对应的区域不显示。
- 活动页的图片拼贴复用同一个查看器。

#### 画廊数据

每张发布照片显式引用自动发现的资产；文件存在不等于内容发布：

```ts
{
  asset: "gallery-2026-08-28",
  author: "摄影者昵称", // 可选，无默认值；支持 unknown/anonymous
  title: { zh: "照片标题", en: "Photograph title" }, // 可选
  caption: { zh: "说明", en: "Caption" } // 可选
}
```

- 源图路径必须有第一层项目目录；项目名和 basename 符合 `[a-z0-9-]+`。ID 为项目名加 basename，不包含扩展名或中间子目录，保留多图序号。
- 同项目 basename 唯一，拼接后的 ID 全局唯一；跨扩展名同名、拼接碰撞、非法路径和符号链接均报错。
- `content/photo-manifest.generated.ts` 自动包含 ID、source、EXIF 方向解释后的 width/height、可推导 date，以及精确的资产 ID 类型。生成物不提交，禁止手工覆盖。
- 日期统一从 basename 的严格、有效 `YYYY-MM-DD` 片段推导，不限页面；有推导值时禁止重复手填，无推导值时可手填或省略。非法日期、多日期歧义报错。
- 内容 ID 默认复用资产 ID；同集合内检查 ID 和资产重复，跨集合允许复用。未被任何发布内容（含主视觉）引用的源图阻止构建。
- author、title、caption、alt、focalPoint 是内容位置的可选人工信息。双语字段必须成对填写，焦点采用 0–100 有限百分比；作者无默认值。
- gallery 自动按日期倒序，同日保持配置顺序，无日期排最后且保持配置顺序。events 保持人工顺序。
- 冠军以正整数 issue 自动关联 contests-issueN，按期号数值倒序；主题和作者可选，照片日期在灯箱有值才展示。当期主视觉显式引用。
- 各 npm 开发、检查、构建入口自动准备 manifest；内容检查不编码图片。图片流水线按内容摘要缓存、验证变体并清理陈旧产物，部署照片 URL 使用重新验证缓存。

### 6.5 关于我们

- 首屏主标题为“不止是虚拟影像，更是同频的视野。”，说明为“面向所有 VRChat 摄影爱好者，一起探索镜头边界。”；英文按相同语义提供。
- 页面依次包含 `01 / MANIFESTO`、`02 / CONNECT`、`03 / SUPPORT` 和 `04 / TEAM`。
- `01 / MANIFESTO` 保留社团介绍，定位对象只包括 VRChat 摄影爱好者，不再包含视频创作者。
- 展示 QQ、VRChat、Discord、抖音、Bilibili 五个平台。
- 每个平台必须配置账号名称和有效外部链接。
- 五个平台直接显示二维码；默认根据相同外部链接在构建时生成，必要时可用官方二维码图片覆盖。
- QQ 需要可访问的加群链接，不能只配置群号。
- 桌面端继续使用五列平台卡片；移动端改为紧凑横向卡片并限制二维码尺寸，控制增加两个 section 后的页面长度。
- `03 / SUPPORT` 主标题为“一份支持，让更多光影赛事发生”。引言为：“我们是由 VRChat 摄影爱好者自发组成的小众社群，至今所有活动都靠大家用爱发电。你的每一份赞助，都将直接用于摄影比赛奖金、创作奖品与主题活动落地，让更多热爱虚拟摄影的人，能在镜头里被看见。”
- 赞助用途为主题摄影赛事的奖金与奖品、大型创作活动的支持、优秀作品的推广与展映、社群创作资源的补给。
- Support 不提供付款、赞助表单或金额入口，只使用现有 QQ 群链接作为联系入口。联系语为：“赞助与合作可在 QQ 群联系社团负责人，备注「社团赞助」；所有支持，我们都会在社群内公开致谢。”
- `04 / TEAM` 主标题为“在镜头之外，他们同样重要”，引言为“PrismShot 运营团队，驱动社团日常与所有创作项目。”
- Team 按林褀／创始人、LukiJ／负责人、`~KY39~`／管理员、`UMI`／网站制作人的顺序展示；英文职务依次为 `Founder`、`Lead`、`Administrator`、`Web Producer`。
- Team 使用四张统一比例的人物卡片；正式照片提供前使用明确的品牌化占位素材，替换照片不改变组件结构。
- 页面底部显示简短隐私说明，不另建独立隐私页面。

### 6.6 一周年摄影赛（可选）

- 页面中英文名称分别为“一周年摄影赛”和 `Anniversary Photo Contest`。
- 首版为独立的“敬请期待”占位页，不提前编写赛程、规则、报名方式或其他未经确认的信息。
- 页面沿用内容页的导航、页脚和暗色棱镜视觉，不使用未提供的摄影素材；主视觉以 `ONE / YEAR`、一周年摄影赛和“敬请期待”构成，英文对应 `Anniversary Photo Contest` 与 `Coming soon`。
- 页面使用普通顶级导航入口，不作为 About 子页面，也不并入常规主题赛页面。
- `PRISMSHOT_ANNIVERSARY=1` 时允许该占位页用于正式发布；“敬请期待”是有意展示的状态，不作为发布门禁中的未完成内容。

## 7. 响应式与兼容性

- 桌面端提供完整沉浸效果。
- 移动端保证所有内容和功能可用，但允许简化水晶、视差、流光、布局和悬浮元素。
- 桌面悬停行为在触屏设备上必须提供点击替代。
- 支持 Chrome、Edge、Firefox、Safari 的当前及前一个主要版本，以及主流 iOS Safari 和 Android Chrome。
- 不支持 Internet Explorer。
- 不支持滤镜或性能不足的浏览器显示静态水晶降级效果，但内容与导航仍然可用。

## 8. 无障碍

目标为 WCAG 2.2 AA，至少包括：

- 导航、菜单、日历、手风琴、语言切换和大图查看器均可通过键盘操作。
- 键盘焦点清晰可见，且不被吸附导航或悬浮元素完全遮挡。
- 正文和交互控件满足相应对比度要求。
- 信息不能只依赖颜色表达。
- 内容图片在取得描述时提供有意义的中英文替代文本；尚无描述时使用当前语言的通用摄影作品标签，纯装饰元素从辅助技术中隐藏。
- 用户启用“减少动态效果”时，关闭视差、位移动画和非必要页面过渡。
- 大图查看器和移动菜单正确管理焦点，并可使用键盘退出。

## 9. 图片与性能

### 9.1 图片构建

- 维护者添加原图并填写内容配置后，构建过程自动生成缩略图与多档响应式 WebP/AVIF。
- 响应式图片不设置 1600 像素的源图宽度硬门槛；窄图使用不超过原图宽度的自适应档位，不执行放大。
- 移除网页不需要的 EXIF 元数据。
- 网页不直接发布超大摄影原图。
- Logo、二维码等素材根据用途保留 SVG 或 PNG。
- 图片处理流程与 Cloudflare 解耦，在普通构建环境中也能运行。
- 正式站点的字体、图标、内容图片和二维码生成依赖均随源码或构建产物发布，不保留原型中的 Unsplash、Google Fonts 或公共 CDN 运行时依赖。

### 9.2 性能目标

- LCP ≤ 2.5 秒。
- INP ≤ 200 毫秒。
- CLS ≤ 0.1。
- 分别检查桌面和移动端。
- 通过首屏资源优先加载、响应式图片、画廊懒加载、预留图片尺寸和移动端动效降级实现目标。
- 现场指标会受托管与访客网络影响，以上数值是上线后的监测目标；发布前使用一致的实验环境进行基准检查。

## 10. SEO、分享与隐私

### 10.1 SEO 与分享

- 每个页面提供独立的中英文标题和描述。
- 配置 canonical URL 和中英文 `hreflang`。
- 生成 `sitemap.xml` 与 `robots.txt`。
- sitemap 只包含构建时已启用的页面。
- 提供 favicon 和统一社交分享封面。
- 正式站点允许索引；分支预览站点禁止索引。

### 10.2 分析与隐私

- 首版只启用 Cloudflare Web Analytics，不接入其他分析服务。
- 通过 Cloudflare Pages 后台启用自动 Beacon，不在源码中加入其他统计 SDK。
- “关于我们”底部的隐私说明应说明：网站不设账号、不接收表单数据，并使用 Cloudflare Web Analytics 获取聚合访问与性能数据。

## 11. 部署与域名

- 目标平台：Cloudflare Pages。
- 构建命令：`next build`。
- 输出目录：`out`。
- 规范地址：`https://prismshot.top`。
- 使用构建环境变量（例如 `NEXT_PUBLIC_SITE_URL`）配置规范站点地址。
- `www.prismshot.top` 和生产 `*.pages.dev` 地址永久重定向到 `https://prismshot.top`。
- 分支预览地址保持独立，并禁止搜索引擎收录。
- `main` 分支自动发布到正式站点；其他分支或 Pull Request 生成预览部署。
- 内容或图片修改必须先通过构建与校验，再合并发布。

## 12. 自动校验与验收

### 12.1 构建门槛

- 代码检查、类型检查和静态构建通过。
- 内容中的必填 `zh`、`en` 文本均非空。
- 开发和分支预览允许使用明确标记的占位内容；生产构建检测到仍带占位标记的必填内容或素材时失败。
- 一周年摄影赛在功能开关开启时显示的“敬请期待”属于已确认内容，不触发生产占位门禁。
- 自动校验同时覆盖周年页开关的关闭与开启状态：关闭时两个路由、导航入口和 sitemap 条目均不存在；开启时中英文路由、导航入口和 sitemap 条目同时存在。
- 配置引用的本地图片文件存在。
- 同一内容集合中的 ID 唯一。
- 照片日期必须为有效 ISO 日期或省略；活动与主题赛状态计算所需日期必须明确提供。
- 外部链接可解析为合法 HTTPS URL。
- 构建时不联网确认第三方链接是否可访问；QQ 邀请链接等由发布前人工验证。

### 12.2 自动浏览器冒烟测试

仅保留三个轻量 Chromium 场景：

1. 桌面首页导航与中英文切换。
2. 活动页手风琴与日历月份边界。
3. 移动端折叠菜单与画廊大图查看器。

### 12.3 发布前人工检查

- 目标桌面浏览器。
- iOS Safari 与 Android Chrome 的真实设备或等效环境。
- WCAG 2.2 AA 关键路径。
- Core Web Vitals 实验室基准。
- 所有社交账号、投稿和投票外链。
- 中英文内容、图片署名和授权状态。
